# Release Notes — v1.91.0.0.0.1

> 日期: 2026-09-22 · 目标上游: Boost 1.91.0 (`BOOST_VERSION 109100`)
> **正式版补丁** (模块封装版本 0.0.1)。模块/feature 计数与可消费面与
> `1.91.0.0.0.0` (原 tag `b1.91.0w0.0.0`) **完全一致**; 变更仅为版本/tag 命名迁移
> 与一处 Windows 构建修复。完整增量见 §4。

## 1. 这是什么

使用 [mcpp](https://github.com/mcpp-community/mcpp) 构建工具对 Boost 库做的
C++23 named modules 封装: 消费者 `import boost.filesystem;`
（或汇总 `import boost;`）, API 拼写与上游一致, 无需 `#include`。

本补丁继首个正式版 `1.91.0.0.0.0` (2026-09-21) 之后发布, **不改变模块面**;
它在修正后的纯数字版本/tag 命名下重切同一内容, 并合入一处仅影响 Windows 的构建
修复。逐库的完整已知限制披露见上一版发布记录
([`b1.91.0w0.0.0`](b1.91.0w0.0.0.md)); 仍然有效的条目原样适用（§5）。

## 3. 版本/Tag 命名迁移（对固定版本消费方为破坏性变更）

版本字符串由 `b<boost>w<封装>` 改为**六段纯数字 `v<boost版本>.<封装版本>`**：

| | 旧 | 新 |
|---|---|---|
| git tag | `b1.91.0w0.0.0` | `v1.91.0.0.0.1` |
| `[package].version` | `b1.91.0w0.0.0` | `1.91.0.0.0.1` |
| 下游声明 | `tag = "b1.91.0w0.0.0"` | `tag = "v1.91.0.0.0.1"` |

mcpp 的版本语法要求首字符为数字且数值核心不接受字母, 旧字符串会让每个按版本
引用它的消费者发出 `not a version RANGE` 警告。开头的 `v` 只属于 git tag ——
`[package].version` 与下游 `version = "..."` 必须省略; mcpp 发布约定在推导
tag/tarball URL 时会自动补上 `v`。历史 tag（`b1.91.0w0.0.0*`）及其发布记录/
changelog 条目保持不变, 视为不可变。

> **现有消费者需操作**: 将依赖声明中的 `tag = ...`（或 `rev = ...`）更新为
> `v1.91.0.0.0.1`。

## 4. 自 b1.91.0w0.0.0 以来的变更

- **版本/tag 命名方案** —— `[package].version` 现为 `1.91.0.0.0.1`, 对应 tag
  `v1.91.0.0.0.1`; README / usage / architecture 文档与发布 runbook 已切换到
  纯数字方案（见 §3）。
- **Windows 构建修复 (`BOOST_THREAD_BUILD_LIB`)** —— 该 define 从私有的
  `[features.thread].flags` 移回基础 `[build].flags`（按 glob 作用于
  `deps/boost/libs/thread/src/**`）。mcpp test 无视 feature 选择、恒全量编译基础
  `[build].sources`, 因此 Windows 下 thread 未激活时 `win32/thread.cpp` 会在宏
  缺失的情况下引用 `tss_cleanup_implemented()`（其定义在 `tss_pe.cpp` 中被
  `BOOST_THREAD_BUILD_LIB` 条件编译掉）, 导致链接失败。按 glob 的形式使该 flag
  仍只作用于 thread 库 TU, 且照旧不传播给消费者。
- **生成器同步** —— 更新 `scripts/gen_features.py`, 使生成块与移动后的 flag
  保持一致。

无模块、feature、计数或 API 变更; 支持的库集合不变。

## 5. 已知限制

与 `1.91.0.0.0.0` 一致, 因 mcpp package index 集成 (T3) 仍待做, 在该版中保持
全量披露。仍然有效的条目（工具链硬限制、gcc 16.1 缺陷家族、纯 include-only 库
名单、平台/覆盖缺口、以及 11 个 M13 暂缓库）详见
[`b1.91.0w0.0.0§4`](b1.91.0w0.0.0.md#4-已知限制全量披露) 与
[架构文档 §4](../architecture.md#4-已知限制-消费者须知)。

## 6. 打包状态

正式版的发布门槛通常包含 mcpp package index 上架 (T3 的 `boost.lua` 集成 +
registry 消费 probe)。该工作仍安排在本次 tag **之后** (它依赖不可变的 tag),
因此本版本通过使用文档所述的 git 依赖消费。也正因如此, 上文已知限制保持全量
披露, 未做正式版的精简。

## 7. 报告问题

提交 issue 前, 请先区分**封装问题**与**编译器缺陷**; 指引与
[`b1.91.0w0.0.0§7`](b1.91.0w0.0.0.md#7-报告问题) 一致。简言之: gcc 16.1 与
clang/llvm 的 ICE、源位置上限属编译器缺陷（附最小复现）; 疑似封装问题请附
编译器 + 平台 + 依赖声明 + 最小复现 TU; mingw / 真 MSVC 反馈同样欢迎。
