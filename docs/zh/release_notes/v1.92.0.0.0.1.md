# Release Notes — v1.92.0.0.0.1

> 日期: 2026-10-26 · 目标上游: Boost 1.92.0 (`BOOST_VERSION 109200`)
> **正式版补丁** (模块封装版本 0.0.1), 也是**本仓库的最后一个版本**。模块/feature
> 计数与可消费面与 `1.92.0.0.0.0` **完全一致**; 变更仅为下述停止维护提示与迁移交接。

## 1. 本仓库已停止维护

Boost 模块封装已迁移至 **[mcpplibs/boost-m](https://github.com/mcpplibs/boost-m)**,
包名称迁移为 **`mcpplibs.mwrap.boost`**。后续开发、修复与 Boost 版本升级都在新仓库进行;
本仓库定格在 `1.92.0` 快照 (tag `v1.92.0.0.0.0` 仍然有效且不可变)。

对需要后续更新的使用者, 迁移是必须的:

| | 本仓库 (定格) | 后继仓库 |
|---|---|---|
| 源码 | `ZheFeng7110/boost-module` | [`mcpplibs/boost-m`](https://github.com/mcpplibs/boost-m) |
| 包名 | `ZheFeng7110.boost` | **`mcpplibs.mwrap.boost`** |
| 最新版本 | `v1.92.0.0.0.1` (本 tag) | 见新仓库的 release |

当前依赖声明写法以新仓库 README 为准: 使用上表中的新包名, 并按新仓库说明操作。
迁移不改变 C++ API 拼写 (`import boost.<lib>;` / `import boost;`, 导出的 `boost::`
实体不变)。

## 2. 这是什么

使用 [mcpp](https://github.com/mcpp-community/mcpp) 构建工具对 Boost 库做的
C++23 named modules 封装: 消费者 `import boost.filesystem;`（或汇总 `import boost;`）,
API 拼写与上游一致, 无需 `#include`。封装层与 Boost 上游同为 BSL 许可。

本补丁继 `1.92.0.0.0.0` (2026-10-10) 之后发布, 不改变任何模块、feature、计数或导出符号。
逐库的完整已知限制披露见 [`v1.92.0.0.0.0`](v1.92.0.0.0.0.md), 原样适用。

## 3. 自 v1.92.0.0.0.0 以来的变更

- **构建期提示**: `build.mcpp` 现在每次运行都会调用 `mcpp::warning(...)`, 说明该库不再
  维护, 并给出后继仓库与新包名。该提示归属于包名、不会让构建失败; 构建缓存命中时
  mcpp 会重放它。整个工程无事可做的 no-op 构建仍不输出任何内容 (它根本不会到达
  `build.mcpp` 阶段) —— 改动任一源码即可再次看到提示。
- **文档**: `README.md`、`README_zh.md`、`docs/usage.md`、`docs/zh/usage.md` 顶部
  加上停止维护/迁移提示。
- **版本**: `[package].version` 现为 `1.92.0.0.0.1`; 消费示例与发布 runbook 指向
  tag `v1.92.0.0.0.1`。

无模块、feature、计数或 API 变更; 支持的库集合不变。

## 5. 已知限制

与 `v1.92.0.0.0.0` 一致, 并在该版全量披露: gcc 16.1 缺陷家族、
`features = ["all"]` 触及 clang/llvm 源位置上限、纯 include-only 库名单、
mingw / 真 MSVC 不承诺。详见
[`v1.92.0.0.0.0§已知限制`](v1.92.0.0.0.0.md) 与
[架构文档 §4](../architecture.md#4-已知限制-消费者须知)。

## 6. 报告问题

本仓库不再接受修复。请到
[mcpplibs/boost-m](https://github.com/mcpplibs/boost-m) 报告问题; 「封装问题 vs 编译器
缺陷」的判别指引不变（封装问题附编译器 + 平台 + 依赖声明 + 最小复现 TU, 编译器 ICE 附
最小复现）。
