# Release Notes — b1.91.0w0.0.0

> 日期: 2026-09-21 · 目标上游: Boost 1.91.0 (`BOOST_VERSION 109100`)
> **正式版**: boost-module 的首个正式版 (模块封装版本 0.0.0)。
> 上游 Boost API 拼写与官方一致; 封装层自身不承诺 ABI/API 稳定性, 仍在
> 推进的唯一打包项见 §6。

## 1. 这是什么

使用 [mcpp](https://github.com/mcpp-community/mcpp) 构建工具对 Boost 库做的
C++23 named modules 封装: 消费者 `import boost.filesystem;`
（或汇总 `import boost;`）, API 拼写与上游一致, 无需 `#include`。

这是继 2026-09-09 `b1.91.0w0.0.0-preview` 之后的正式版。模块/feature 计数不变;
本周期的工作收口了若干历史导出盲区, 并新增了对一部分 `BOOST_*` 特性宏的受支持
自定义通道。完整增量见 §5。

## 3. 消费者注意事项（精选陷阱）

- **宏永不跨模块边界**: `BOOST_PP_*`、`BOOST_FOREACH`、`BOOST_DESCRIBE_*`、
  `BOOST_TEST_*` 等宏 API 只能来自 `#include`（§4.3 名单的 20 库请 include）。
- **消费者必须自带 std 表面**: `import std;` 或 include 标准头 —— boost 实体
  签名引用 std 类型的运算符在纯 import TU 不可见（设计使然）。
- **`--features all` 不要在 clang 下用**: 全量 CMI ~2.98GB 超 clang 2^31
  源位置上限, **推荐逐库 import**; gcc 侧同限未实测。
- **特性宏仅通过 profile 自定义**: 受支持子集以 `backend-<axis>-<impl>` feature
  暴露, 用 `backend = "log-avx2"`（或 `features = ["backend-..."]`）选择; 其余
  任意 `BOOST_*` 宏须走 include-only 逃生。见架构文档 §3.1。
- **`boost.version` 宏与拼写互斥**: 同一 TU 内 `#include <boost/version.hpp>`
  的宏会吞掉 `boost::BOOST_VERSION` 拼写 —— 二选一。
- 诸如 MSVC `assert` 不短路、program_options 在 `store()` 抛异常、parameter
  关键字 `_index` 等细节, 见架构/设计汇总 §8。

## 4. 已知限制（全量披露）

### 4.1 工具链/标准硬限制

| 限制 | 消费方式 |
|---|---|
| clang `--features all` 超 2^31 源位置上限 | 逐库 import; gcc 侧未实测 |
| 特性宏默认构建期固定 | **有限自定义**: 受支持宏用 profile feature (`backend = "<axis>-<impl>"`, 触发包重编译); 任意宏走 include-only 逃生 (见 §3) |
| filesystem v3 / thread v2 / stacktrace basic 固定 | 拼写按对应上游版本 |
| algorithm 无 regex 面 (gcc abi-tag) | regex 需求另行 include |
| iostreams 外部后端 (zlib/gzip/bzip2/lzma/zstd) 与 cobalt ssl 不入包 (OpenSSL) | 自备外部依赖 |
| math tr1、container dlmalloc/alloc_lib、process 聚合头不入包 | 用主 API 面 |
| log event_log 手写 mc.exe 桩不入包; dump_avx2/ssse3 不在基础构建内 | 平台裁剪; 需 dump 后端时用 `backend-log-ssse3` / `backend-log-avx2` |
| type_erasure `any<>` 动态分发路径 clang-msvc 模块消费者不可实例化 | 模块面/概念模板可用 |
| `numeric::interval<double>` 模块面不可实例化 | include 头文件 |
| 上游未加 `inline` 的内部链接 `const`/`constexpr` 对象仍不可导出 | 逐个 vendored `inline` 改造或提供替代拼写 |
| 变量模板初始化器仅对字面 `boost::...` 与相对限定名补跨模块 `.deps` 边 | 宏展开/别名/裸非限定名需显式 import |
| mcpp package index 上架 (T3 `boost.lua`) | 本次未做; 用 git 依赖消费 (见 §6) |

### 4.2 gcc 16.1 缺陷家族（编译器 bug, 本封装无法修复）

- exception CMI pendings (库已降级 include-only);
- variant `apply_visitor` 自由函数重载 ICE (用成员版本);
- 消费者自定义异常 clone_impl thunk 缺失;
- CMI/GMF 合并冲突等。

**gcc 消费方式三分规则**: ① 正常 import; ② import + 补标准头
(`<new>`/`<typeinfo>`); ③ 纯 include。逐库核实方法见架构文档 §4.2。

### 4.3 纯 include-only 库名单 (20 库, 无 feature 无模块)

- **宏驱动 (16)**: preprocessor / mpl / fusion / proto / spirit / xpressive /
  typeof / vmd / phoenix / parameter / metaparse / function_types / tti /
  local_function / msm / foreach。
- **降级 (4)**: exception、describe、openmethod、scope_exit。

### 4.4 平台与覆盖缺口

- **mingw**: 无 CI 腿, 不承诺 (已知: thread `sleep_for` 挂起、
  url `BOOST_URL_RETURN_EC` 宏冲突)。
- **真 MSVC (cl)**: 从未验证, 不承诺 (CI windows 腿是 clang-msvc 风味)。
- **macOS**: Mach-O typeinfo 不跨模块边界合并 → 精确异常 catch 落空;
  退回 `catch (const std::exception&)`。
- **linux-gnu (glibc)** 腿未本地验证 (musl 交叉构建代表 POSIX 面)。

### 4.5 不支持的库（M13 暂缓, 11 库）

> context / fiber / coroutine (asm)、locale (ICU)、mpi、python、
> parameter_python、graph_parallel、compute (OpenCL)、mysql / redis (OpenSSL)

本周期零改动; 重启评估仍待定。

## 5. 预览版以来的变更 (b1.91.0w0.0.0-preview → b1.91.0w0.0.0)

- **特性宏 profile (`backend-*`)** —— 消费者可选 `BOOST_*` 特性宏的受支持通道。
  首批: `backend-log-ssse3` / `backend-log-avx2`（Boost.Log dump 后端）。
  `build.mcpp` 在模块扫描前校验同轴互斥与目标架构; profile 名单由
  `scripts/gen_features.py` (`PROFILE_FEATURES`) 与 `scripts/profiles.lst` 维护。
- **变量模板导出** —— `boost::pfr::tuple_size_v`、`boost::hana::int_c` /
  `integral_c` 等 21 个模块的 363 条变量模板现已导出; 生成器可分类 libclang
  不透明的 `UNEXPOSED_DECL` 变量模板, 并恢复其跨模块初始化器依赖 (字面量 +
  相对限定名)。
- **内部链接对象导出** —— range adaptor 管道语法
  (`vec | boost::adaptors::reversed`)、`boost::extents` / `boost::indices`、
  accumulators `extract::*`、mqtt5 `prop::*` 已通过 vendored `inline` 修补导出;
  不再需要此前的替代拼写。
- **include-only 消费者的 Win32 ABI 对齐** —— vendored `config` 修补使包内 TU
  与消费者 TU 的 `BOOST_HAS_THREADS` / `BOOST_ALL_NO_LIB` 一致, 修复 clang-msvc
  的 `boost_log_abi` mismatch。
- **导出生成器加固** —— 生成器固定 MinGW sysroot bootstrap、统一 `clang++` gate
  与 libclang 解析宏, 并按修正后的基线重建 `process.inc`。
- **构建修复** —— `boost.cppm` 生成到 `MCPP_OUT_DIR`, 消除交叉构建竞争。
- **CI** —— group A/B 改为并行 job, examples 对两者同时门禁; 升级 toolchain 与
  mcpp 缓存版本。
- **文档** —— 补齐完整英文文档 (中文移至 `*_zh` / `docs/zh`)。

## 6. 打包状态

正式版的发布门槛通常包含 mcpp package index 上架 (T3 的 `boost.lua` 集成 +
registry 消费 probe)。该工作被有意安排在本次 tag **之后** (它依赖不可变的 tag),
因此本版本通过使用文档所述的 git 依赖消费。也正因如此, 上文已知限制保持全量披露,
未做正式版的精简。

## 7. 报告问题

提交 issue 前, 请先区分**封装问题**与**编译器缺陷**:

1. **gcc 16.1 缺陷家族**（§4.2: ICE、重复符号、pendings、thunk 缺失等）是编译器
   bug; 欢迎上游可复现的最小例。封装只能绕过, 无法修复。请在 issue 中注明编译器
   版本并附最小复现（标注 "gcc-16 module bug"）。
2. **clang/llvm 问题**（如 2^31 源位置上限）同样是无可调 flag 的工具链硬限制。
3. **疑似封装问题**（实体缺失 / 导出拼写不符 / 链接错误 / 文档与实际不符）:
   请附编译器 + 平台 + 依赖声明（`features` 配置）+ 最小复现 TU。
4. mingw / 真 MSVC（§4.4 不承诺范围）上的失败也欢迎反馈, 作为后续支持决策参考。
