# Release Notes — v1.91.0.0.1.0

> 日期: 2026-09-22 · 目标上游: Boost 1.91.0 (`BOOST_VERSION 109100`)
> **正式版次版本** (模块封装版本 0.1.0)。模块/feature 计数与可消费面与
> `1.91.0.0.0.1` **完全一致**; 变更仅为包标识迁移、发布打包自动化与示例刷新。
> 完整增量见 §4。

## 1. 这是什么

使用 [mcpp](https://github.com/mcpp-community/mcpp) 构建工具对 Boost 库做的
C++23 named modules 封装: 消费者 `import boost.filesystem;`
（或汇总 `import boost;`）, API 拼写与上游一致, 无需 `#include`。

本版本继 `1.91.0.0.0.1` (2026-09-22) 之后发布, **不改变模块面**;
它变更了 mcpp 依赖标识, 并把发布打包移入 CI。逐库的完整已知限制披露见首个正式版
发布记录 ([`b1.91.0w0.0.0`](b1.91.0w0.0.0.md)); 仍然有效的条目原样适用（§5）。

## 2. 内容清单

| 项 | 数量 | 说明 |
|---|---|---|
| 模块接口 | **116** | `import boost.<lib>;` / `import boost;`（动态汇总, re-export 当前激活库） |
| 库 feature | **118** | 116 模块 feature + `log` / `unit_test_framework` 两个无模块 feature |
| profile feature | **2** | opt-in `backend-log-ssse3` / `backend-log-avx2`（x86_64, Boost.Log dump 后端） |
| 默认集 | **49 库闭包** | 依赖声明默认激活; 其余 opt-in (`features = [...]`) |
| 编译库 include-only | **2** | log、test（`unit_test_framework` 双形态） |
| 纯 include-only | **20** | 宏驱动 16 + 降级 4（直接 `#include` 上游头, 可与 import 混用） |
| 封装可消费总数 | **138** | = 116 + 2 + 20 |
| 测试 | 141 smoke | 默认集 141/141 通过; CI 四腿 A/B 两组门禁 |

- **平台**: CI 四腿覆盖 windows (clang-msvc 风味) / linux (gcc 16, llvm) /
  macos (llvm, arm64)。**mingw 与真 MSVC (cl) 不承诺**（见首个正式版发布记录 §4.4）。
- **许可**: 封装层 BSL; Boost 上游 BSL。
- **版本常量**: `import boost.version;` → `boost::BOOST_VERSION` /
  `boost::BOOST_LIB_VERSION`（默认集内, `import boost;` 自动可用）。

快速上手与依赖声明示例见[使用文档](../usage.md)与[架构文档](../architecture.md)。

## 3. 包标识变更（对消费者为破坏性变更）

mcpp 依赖标识由 `boost.boost` 改为 **`ZheFeng7110.boost`**：

| | 旧 | 新 |
|---|---|---|
| `[package].namespace` | `boost` | `ZheFeng7110` |
| 下游声明 | `boost.boost = { ... }` | `ZheFeng7110.boost = { ... }` |

这是包命名空间（`namespace` + `name`），与 C++ 侧无关: 模块名
（`import boost.<lib>;`）、汇总 `import boost;`、导出的 `boost::` 命名空间**均不变**。
版本/tag 方案也不变（本次为 `v1.91.0.0.1.0`）。

> **现有消费者需操作**: 将依赖键名由 `boost.boost` 改为 `ZheFeng7110.boost`
> （`[dependencies]` 内联形式与 `[dependencies.<key>]` 表形式均需改），并若按版本固定
> 则把 `tag = ...` / `rev = ...` 更新为 `v1.91.0.0.1.0`。

## 4. 自 v1.91.0.0.0.1 以来的变更

- **包命名空间重命名** —— `[package].namespace` 现为 `ZheFeng7110`, mcpp 依赖标识因此
  从 `boost.boost` 变为 `ZheFeng7110.boost`; README / usage / architecture 文档与三个
  示例已同步（见 §3）。无 C++ 模块或导出变更。
- **GitHub Release 自动化工作流** —— 新增 `.github/workflows/release.yml`, 在 tag push
  时运行: 抽取 `docs/release_notes/<tag>.md` 作为 release body（文件缺失则运行失败）,
  运行新增的 `scripts/package-source.sh` 生成源码归档
  （`.zip` / `.tar.gz` / `.tar.xz` / `.7z` + `.sha256` 校验和）, 并附到标题为
  `Release <tag>` 的 release; 以 `-preview` 结尾的 tag 标记为 prerelease。发布 runbook
  （中英）已记录自动化流程与手动兜底方式。
- **示例刷新** —— `examples/git_dep_usage` 指向当前 revision, 并移除已提交的过期
  `mcpp.lock`（由 mcpp 重新解析）。

无模块、feature、计数或 API 变更; 支持的库集合不变。

## 5. 已知限制

与首个正式版一致, 因 mcpp package index 集成 (T3) 仍待做, 在该版中保持全量披露。
仍然有效的条目（工具链硬限制、gcc 16.1 缺陷家族、纯 include-only 库名单、平台/覆盖
缺口、以及 11 个 M13 暂缓库）详见
[`b1.91.0w0.0.0§4`](b1.91.0w0.0.0.md#4-已知限制全量披露) 与
[架构文档 §4](../architecture.md#4-已知限制-消费者须知)。

## 6. 打包状态

正式版的发布门槛通常包含 mcpp package index 上架 (T3 的 `boost.lua` 集成 +
registry 消费 probe)。该工作仍安排在本次 tag **之后** (它依赖不可变的 tag),
因此本版本通过使用文档所述的 git 依赖消费。也正因如此, 上文已知限制保持全量披露,
未做正式版的精简。源码归档现由发布工作流自动生成（§4）。

## 7. 报告问题

提交 issue 前, 请先区分**封装问题**与**编译器缺陷**; 指引与
[`b1.91.0w0.0.0§7`](b1.91.0w0.0.0.md#7-报告问题) 一致。简言之: gcc 16.1 与
clang/llvm 的 ICE、源位置上限属编译器缺陷（附最小复现）; 疑似封装问题请附
编译器 + 平台 + 依赖声明 + 最小复现 TU; mingw / 真 MSVC 反馈同样欢迎。
