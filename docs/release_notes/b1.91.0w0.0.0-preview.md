# Release Notes — b1.91.0w0.0.0-preview

> 日期: 2026-09-09 · 目标上游: Boost 1.91.0 (`BOOST_VERSION 109100`)
> **预览版**: 这是 boost-module 的首个公开预览, 模块封装版本 0.0.0。
> API 表面 (导出实体集合) 在正式版前仍可能有增删, 封装层不承诺任何
> 稳定性; 上游 Boost API 拼写与官方一致。

## 1. 这是什么

使用 [mcpp](https://github.com/mcpp-community/mcpp) 构建工具对 Boost 库做的
C++23 named modules 封装: 消费者 `import boost.filesystem;`
（或汇总 `import boost;`）, API 拼写与上游一致, 无需 `#include`。

## 2. 内容清单

| 项 | 数量 | 说明 |
|---|---|---|
| 模块接口 | **116** | `import boost.<lib>;` / `import boost;`（动态汇总, re-export 当前激活库） |
| feature | **118** | 116 模块 feature + `log` / `unit_test_framework` 两个无模块 feature |
| 默认集 | **49 库闭包** | 依赖声明默认激活; 其余 opt-in (`features = [...]`) |
| 编译库 include-only | **2** | log、test（`unit_test_framework` 双形态） |
| 纯 include-only | **20** | 宏驱动 16 + 降级 4（直接 `#include` 上游头, 可与 import 混用） |
| 封装可消费总数 | **138** | = 116 + 2 + 20 |
| 测试 | 141 smoke | 默认集 141/141 通过; CI 四腿 A/B 两组全量门禁 |

- **平台**: CI 四腿覆盖 windows (clang-msvc 风味) / linux (gcc 16, llvm) /
  macos (llvm, arm64)。**mingw 与真 MSVC (cl) 不承诺**（见 §4.4）。
- **许可**: 封装层 BSL; Boost 上游 BSL。
- **版本常量**: `import boost.version;` → `boost::BOOST_VERSION` /
  `boost::BOOST_LIB_VERSION`（默认集内, `import boost;` 自动可用）。

快速上手与依赖声明示例见[使用文档](../usage.md)与[架构文档](../architecture.md)。

## 3. 消费者注意事项（精选陷阱）

- **宏永不跨模块边界**: `BOOST_PP_*`、`BOOST_FOREACH`、`BOOST_DESCRIBE_*`、
  `BOOST_TEST_*` 等宏 API 只能来自 `#include`（§4.3 名单的 20 库请 include）。
- **消费者必须自带 std 表面**: `import std;` 或 include 标准头 —— boost 实体
  签名引用 std 类型的运算符在纯 import TU 不可见（设计使然）。
- **`--features all` 不要在 clang 下用**: 全量 CMI ~2.98GB 超 clang 2^31
  源位置上限。**推荐逐库 import**; gcc 侧同限未实测。
- **`boost.version` 宏与拼写互斥**: 同一 TU 内 `#include <boost/version.hpp>`
  的宏会吞掉 `boost::BOOST_VERSION` 拼写, 二选一。
- **特性宏构建期固定**: 消费者无法自定义任何 BOOST_* 特性宏; filesystem v3 /
  thread v2 (`unique_future`) / stacktrace basic 等裁剪见架构文档 §4.1。
- MSVC `assert` 不短路、program_options 异常抛在 `store()`、parameter
  关键字 `_index` 等写法细节见架构文档/设计汇总 §8。

## 4. 已知限制（全量披露）

### 4.1 工具链/标准硬限制

| 限制 | 消费方式 |
|---|---|
| clang `--features all` 超 2^31 源位置上限 | 逐库 import; gcc 侧未实测 |
| 特性宏一律构建期固定 | 无法自定义 BOOST_* 特性宏 |
| filesystem v3 / thread v2 / stacktrace basic 固定 | 按对应上游版本拼写 |
| algorithm 无 regex 面 (gcc abi-tag) | regex 需求另行 include |
| iostreams 外部后端 (zlib/gzip/bzip2/lzma/zstd) 与 cobalt ssl 不入包 (OpenSSL) | 自备外部依赖 |
| math tr1、container dlmalloc/alloc_lib、process 聚合头不入包 | 用主 API 面 |
| log event_log 手写 mc.exe 桩、dump_avx2/ssse3 不入包 | 平台裁剪 |
| type_erasure `any<>` 动态分发路径 clang-msvc 模块消费者不可实例化 | 模块面/概念模板可用 |
| `numeric::interval<double>` 模块面不可实例化 | include 头文件 |
| range pipe 语法 (`vec \| reversed`)、multi_array `boost::extents` 不导出 | 函数形式/容器式构造 |
| accumulators `extract::*`、mqtt5 `prop::*`、hana int_c、pfr::tuple_size_v 等 | 按架构文档 §4.1 替代拼写 |

### 4.2 gcc 16.1 缺陷家族（编译器 bug, 非本封装可根治）

- exception CMI pendings（库已降级 include-only）;
- variant `apply_visitor` 自由函数重载消费者 ICE（用成员版本）;
- 消费者自定义异常 clone_impl thunk 缺失;
- CMI/GMF 合并冲突等。

**gcc 消费方式三分规则**: ① 正常 import; ② import + 补标准头
（`<new>`/`<typeinfo>`）; ③ 纯 include。逐库核实方式见架构文档 §4.2。

### 4.3 纯 include-only 库名单（20 库, 无 feature 无模块）

- **宏驱动 (16)**: preprocessor / mpl / fusion / proto / spirit / xpressive /
  typeof / vmd / phoenix / parameter / metaparse / function_types / tti /
  local_function / msm / foreach。
- **降级 (4)**: exception、describe、openmethod、scope_exit。

### 4.4 平台与覆盖缺口

- **mingw**: 无 CI 腿, 不承诺（已知: thread `sleep_for` 挂起、
  url `BOOST_URL_RETURN_EC` 宏冲突）。
- **真 MSVC (cl)**: 从未验证, 不承诺（CI windows 腿是 clang-msvc 风味）。
- **macOS**: Mach-O typeinfo 跨模块边界不合并 → 精确 catch 落空,
  请以 `catch (const std::exception&)` 兜底。
- **linux-gnu (glibc)** 腿未本地验证（musl 交叉代表 POSIX 面）。

### 4.5 不支持的库（M13 暂缓, 11 个）

> context / fiber / coroutine (asm)、locale (ICU)、mpi、python、
> parameter_python、graph_parallel、compute (OpenCL)、mysql / redis (OpenSSL)

本期零改动; 重启评估将在预览版之后进行。

## 5. 报告问题指引

提交 issue 前，请先区分**封装问题**与**编译器缺陷**：

1. **gcc 16.1 缺陷家族**（§4.2：ICE、重复符号、pendings、thunk 缺失等）
   属编译器 bug，上游可复现的最小样例优先；本封装只能绕过不能根治。
   请在 issue 中注明编译器版本并附最小复现（标注 "gcc-16 module bug"）。
2. **clang/llvm 侧问题**（如 2^31 源位置上限）同样属工具链硬限制，
   无 flag 可调。
3. **疑似封装问题**（实体缺失 / 导出拼写不符 / 链接错误 / 文档与实测矛盾）:
   请附 编译器 + 平台 + 依赖声明（`features` 配置）+ 最小复现 TU。
4. mingw / 真 MSVC 平台的失败（§4.4 不承诺范围）也欢迎反馈,
   用于后续支持决策, 但不视为预览版缺陷。
