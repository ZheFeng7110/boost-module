# Release Notes — b1.91.0w0.0.0

> Date: 2026-09-21 · Target upstream: Boost 1.91.0 (`BOOST_VERSION 109100`)
> **Stable**: first stable release of boost-module (modules wrapper version 0.0.0).
> The upstream Boost API spelling matches the official release. The wrapper layer makes no
> ABI/API stability guarantees of its own; see §6 for the one packaging item still pending.

## 1. What Is This

C++23 named modules wrapper for the Boost libraries built with the
[mcpp](https://github.com/mcpp-community/mcpp) build tool: consumers write
`import boost.filesystem;` (or the umbrella `import boost;`); the API spelling is identical
to upstream, no `#include` needed.

This is the stable release that follows the `b1.91.0w0.0.0-preview` from 2026-09-09. The
module/feature counts are unchanged; the cycle's work closed several long-standing export
blind spots and added a supported channel for customizing a subset of `BOOST_*` feature
macros. See §5 for the full delta.

## 3. Consumer Notes (selected pitfalls)

- **Macros never cross module boundaries**: macro APIs such as `BOOST_PP_*`,
  `BOOST_FOREACH`, `BOOST_DESCRIBE_*`, `BOOST_TEST_*` can only come from `#include`
  (the 20 libraries listed in §4.3 must be included).
- **Consumers must provide their own std surface**: `import std;` or include the standard
  headers — operators on boost entity signatures referencing std types are not visible in a
  pure-import TU (by design).
- **Do not use `--features all` with clang**: the full CMI set is ~2.98GB, exceeding
  clang's 2^31 source-location cap. **Importing libraries one by one is recommended**;
  the same limit has not been verified on the gcc side.
- **Feature macros are customizable only through profiles**: a supported subset is exposed
  as `backend-<axis>-<impl>` features and selected with `backend = "log-avx2"` (or
  `features = ["backend-..."]`); any other `BOOST_*` macro requires the include-only escape.
  See architecture doc §3.1.
- **`boost.version` macro and spelling are mutually exclusive**: within the same TU, the
  macros from `#include <boost/version.hpp>` will swallow the `boost::BOOST_VERSION`
  spelling — pick one.
- For details such as MSVC `assert` not short-circuiting, program_options throwing in
  `store()`, and the parameter keyword `_index`, see the architecture/consolidated design
  §8.

## 4. Known Limitations (full disclosure)

### 4.1 Toolchain/Standard Hard Limits

| Limitation | How to consume |
|---|---|
| clang `--features all` exceeds the 2^31 source-location cap | Import libraries one by one; not verified on the gcc side |
| Feature macros are fixed at build time by default | **Limited customization** via profile features (`backend = "<axis>-<impl>"`, triggers a package recompile); arbitrary macros need the include-only escape (see §3) |
| filesystem v3 / thread v2 / stacktrace basic fixed | Spell per the corresponding upstream version |
| algorithm has no regex surface (gcc abi-tag) | For regex needs, include separately |
| iostreams external backends (zlib/gzip/bzip2/lzma/zstd) and cobalt ssl not packaged (OpenSSL) | Provide external dependencies yourself |
| math tr1, container dlmalloc/alloc_lib, process aggregate headers not packaged | Use the main API surface |
| log event_log hand-written mc.exe stub not packaged; dump_avx2/ssse3 not in the base build | Platform trim; opt into the dump backends with `backend-log-ssse3` / `backend-log-avx2` |
| type_erasure `any<>` dynamic-dispatch path not instantiable by clang-msvc module consumers | Module surface / concept templates work |
| `numeric::interval<double>` module surface not instantiable | Include the header file |
| Internal-linkage `const`/`constexpr` objects that upstream did not mark `inline` still cannot be exported | Solved case-by-case via vendored `inline` patches, or use the alternative spelling |
| Variable-template initializers only contribute cross-module `.deps` edges for literal `boost::...` references and relative qualified names | Macro-expanded / aliased / bare unqualified references need an explicit import |
| mcpp package-index publication (T3 `boost.lua`) | Not done in this release; consume via the git dependency (see §6) |

### 4.2 gcc 16.1 Defect Family (compiler bugs, not fixable in this wrapper)

- exception CMI pendings (library already downgraded to include-only);
- variant `apply_visitor` free-function overload ICE in consumers (use the member version);
- missing clone_impl thunk for consumer-defined exceptions;
- CMI/GMF merge conflicts, etc.

**Three-mode gcc consumption rule**: ① plain import; ② import + supplemental standard
headers (`<new>`/`<typeinfo>`); ③ pure include. For the per-library verification method,
see architecture doc §4.2.

### 4.3 Pure include-only Library List (20 libraries, no feature no module)

- **Macro-driven (16)**: preprocessor / mpl / fusion / proto / spirit / xpressive /
  typeof / vmd / phoenix / parameter / metaparse / function_types / tti /
  local_function / msm / foreach.
- **Downgraded (4)**: exception, describe, openmethod, scope_exit.

### 4.4 Platform and Coverage Gaps

- **mingw**: no CI leg, not guaranteed (known: thread `sleep_for` hangs,
  url `BOOST_URL_RETURN_EC` macro conflict).
- **Real MSVC (cl)**: never verified, not guaranteed (the CI windows leg is the clang-msvc
  flavor).
- **macOS**: Mach-O typeinfo does not merge across module boundaries → precise catch fails;
  fall back to `catch (const std::exception&)`.
- **linux-gnu (glibc)** leg not locally verified (the musl cross build represents the
  POSIX surface).

### 4.5 Unsupported Libraries (M13 deferred, 11)

> context / fiber / coroutine (asm), locale (ICU), mpi, python, parameter_python,
> graph_parallel, compute (OpenCL), mysql / redis (OpenSSL)

Zero changes this cycle; the restart evaluation is still pending.

## 5. Changes Since the Preview (b1.91.0w0.0.0-preview → b1.91.0w0.0.0)

- **Feature-macro profiles (`backend-*`)** — a supported channel for consumer-selected
  `BOOST_*` feature macros. First entries: `backend-log-ssse3` / `backend-log-avx2`
  (Boost.Log dump backends). `build.mcpp` enforces per-axis mutual exclusion and target
  architecture before module scanning; the profile list lives in
  `scripts/gen_features.py` (`PROFILE_FEATURES`) and `scripts/profiles.lst`.
- **Variable-template exports** — `boost::pfr::tuple_size_v`,
  `boost::hana::int_c` / `integral_c`, and 363 variable templates across 21 modules are now
  exported; the generator classifies libclang's opaque `UNEXPOSED_DECL` variable templates
  and recovers their cross-module initializer dependencies (literal + relative qualified
  names).
- **Internal-linkage object exports** — range adaptor pipe syntax
  (`vec | boost::adaptors::reversed`), `boost::extents` / `boost::indices`,
  accumulators `extract::*` and mqtt5 `prop::*` are exported via vendored `inline` patches;
  the previous fallback spellings are no longer required.
- **Win32 ABI harmonization for include-only consumers** — vendored `config` patches keep
  `BOOST_HAS_THREADS` / `BOOST_ALL_NO_LIB` consistent between package TUs and consumer TUs,
  fixing the clang-msvc `boost_log_abi` mismatch.
- **Export-generator hardening** — pinned MinGW sysroot bootstrap for the generator,
  unified `clang++` gate and libclang parse macros, and a rebuilt `process.inc` on the
  corrected baseline.
- **Build fix** — `boost.cppm` is generated into `MCPP_OUT_DIR`, ending cross-build races.
- **CI** — group A/B now run as parallel jobs with examples gated on both; toolchain and
  mcpp cache versions upgraded.
- **Docs** — full English documentation added (Chinese moved to `*_zh` / `docs/zh`).

## 6. Packaging Status

The stable release bar normally includes publishing on the mcpp package index (the `T3`
`boost.lua` integration + registry consumption probe). That work is intentionally scheduled
**after** this tag (it depends on the immutable tag), so this release is consumed through the
git dependency documented in the user guide. Known-limitation disclosure above is kept full
rather than reduced for that reason.

## 7. Reporting Issues

Before filing an issue, distinguish a **wrapper problem** from a **compiler defect**:

1. **gcc 16.1 defect family** (§4.2: ICE, duplicate symbols, pendings, missing thunks, etc.)
   are compiler bugs; upstream-reproducible minimal examples are preferred. This wrapper
   can only work around them, not fix them. Note the compiler version in the issue and
   attach a minimal reproduction (labeled "gcc-16 module bug").
2. **clang/llvm issues** (e.g. the 2^31 source-location cap) are likewise hard toolchain
   limits with no flag to change.
3. **Suspected wrapper problems** (missing entities / exported spelling mismatch / link
   errors / docs contradicting actual behavior): please attach compiler + platform +
   dependency declaration (`features` config) + a minimal reproducing TU.
4. Failures on mingw / real MSVC (§4.4 not-guaranteed scope) are also welcome as feedback
   for future support decisions.
